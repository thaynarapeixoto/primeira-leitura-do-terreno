# Segurança e dados sensíveis

## Não publique dados de clientes

Issues, discussões, exemplos e contribuições deste repositório são públicos. Não envie:

- matrículas;
- certidões;
- contratos;
- documentos pessoais;
- CPF, CNPJ ou contatos;
- assinaturas;
- coordenadas de áreas confidenciais;
- dados de negociação;
- arquivos protegidos por contrato;
- credenciais de sistemas.

## Cuidado com identificação por triangulação

Retirar o nome não basta. Município pequeno, área exata, uso pretendido e data juntos podem identificar um terreno e uma negociação, mesmo sem nenhum dado nominal. Ao montar um exemplo, altere pelo menos um dos elementos que permitiriam a triangulação.

## Como criar um exemplo

Prefira:

- dados totalmente fictícios;
- localização genérica;
- números alterados;
- documentos sem identificação;
- imagens próprias ou autorizadas;
- descrição suficiente para explicar o método, sem revelar o caso.

E declare, no próprio exemplo, que ele é fictício. A declaração vale para quem lê fora de contexto.

## Uso em ferramentas de IA

Antes de enviar qualquer conteúdo:

1. confirme a autorização;
2. remova dados pessoais;
3. retire informações desnecessárias;
4. confira os termos da ferramenta utilizada;
5. mantenha uma cópia segura do documento original;
6. não trate o conteúdo processado como fonte substituta.

## Relato de problema

Se identificar exposição indevida de dados neste repositório, **não amplie a divulgação por uma issue pública.**

Use o canal privado do GitHub: aba **Security**, opção **Report a vulnerability**. O relato fica visível apenas para a responsável pelo repositório.

Descreva o arquivo, a linha e o tipo de dado exposto. Não cole o dado em si.
